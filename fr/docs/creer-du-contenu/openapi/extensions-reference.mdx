Vous pouvez enrichir votre spécification OpenAPI à l’aide d’extensions — des champs personnalisés qui commencent par `x-` le préfixe. Ces extensions vous permettent d’ajouter des informations supplémentaires et d’adapter la documentation de votre API à différents besoins.

GitBook vous permet d’ajuster l’apparence et le fonctionnement de votre API sur votre site publié grâce à une gamme de différentes extensions que vous pouvez ajouter à votre spécification OpenAPI.

Rendez-vous dans notre [section des guides](/fr/docs/creer-du-contenu/openapi/guides) pour en savoir plus sur l’utilisation des extensions OpenAPI pour configurer votre documentation.

<Expandable title="x-page-title | x-displayName">
  Modifiez le nom d’affichage d’un tag utilisé dans la navigation et le titre de la page.

  ```yaml title="openapi.yaml"
  openapi: '3.0'
  info: ...
  tags:
    - name: users
      x-page-title: Utilisateurs
  ```
</Expandable>

<Expandable title="x-page-description">
  Ajoutez une description à la page.

  ```yaml title="openapi.yaml"
  openapi: '3.0'
  info: ...
  tags:
    - name: "users"
      x-page-title: "Utilisateurs"
      x-page-description: "Gérer les comptes et profils utilisateur."
  ```
</Expandable>

<Expandable title="x-page-icon">
  Ajoutez une icône Font Awesome à la page. Voir les icônes disponibles [ici](https://fontawesome.com/search).

  ```yaml title="openapi.yaml"
  openapi: '3.0'
  info: ...
  tags:
    - name: "users"
      x-page-title: "Utilisateurs"
      x-page-description: "Gérer les comptes et profils utilisateur."
      x-page-icon: "user"
  ```
</Expandable>

<Expandable title="parent | x-parent">
  Ajoutez une hiérarchie aux tags pour organiser vos pages dans GitBook.

  <Callout kind="alert">
    `parent` est le nom de propriété officiel dans OpenAPI 3.2+. Si vous utilisez une version d’OpenAPI antérieure à 3.2 (3.0.x, 3.1.x), utilisez `x-parent` à la place.
  </Callout>

  ```yaml title="openapi.yaml"
  openapi: '3.2'
  info: ...
  tags:
    - name: organization
    - name: admin
      parent: organization
    - name: user
      parent: organization    
  ```
</Expandable>

<Expandable title="x-hideTryItPanel">
  Afficher ou masquer le bouton « Tester » pour un bloc OpenAPI.

  ```yaml title="openapi.yaml"
  openapi: '3.0'
  info: ...
  tags: [...]
  paths:
    /example:
      get:
        summary: Exemple de résumé
        description: Exemple de description
        operationId: examplePath
        responses: [...]
        parameters: [...]
        x-hideTryItPanel: true
  ```
</Expandable>

<Expandable title="x-expandAllResponses">
  Développez toutes les sections de réponse par défaut, au lieu d’en afficher une seule à la fois.

  Ajoutez-la à la racine pour l’appliquer à chaque opération. Ajoutez-la sur une opération pour l’appliquer à ce seul point de terminaison.

  ```yaml
  openapi: '3.0'
  info: ...

  # Développer toutes les réponses pour chaque opération
  x-expandAllResponses: true

  paths:
    /pets:
      get:
        summary: Lister les animaux de compagnie
        responses: [...]
        # Désactiver pour une seule opération
        x-expandAllResponses: false
  ```
</Expandable>

<Expandable title="x-expandAllModelSections">
  Développez toutes les sections de modèle/schéma par défaut, en affichant les propriétés d’objets imbriqués sans interaction de l’utilisateur.

  Ajoutez-la à la racine pour l’appliquer à chaque opération. Ajoutez-la sur une opération pour l’appliquer à ce seul point de terminaison.

  ```yaml
  openapi: '3.0'
  info: ...

  # Développer toutes les sections de modèle pour chaque opération
  x-expandAllModelSections: true

  paths:
    /pets:
      post:
        summary: Créer un animal de compagnie
        requestBody: [...]
        responses: [...]
        # Désactiver pour une seule opération
        x-expandAllModelSections: false
  ```
</Expandable>

<Expandable title="x-enable-proxy">
  Faites transiter les requêtes « Tester » via le proxy OpenAPI de GitBook.

  Ajoutez-la à la racine pour l’appliquer à chaque opération. Ajoutez-la sur une opération pour l’appliquer à ce seul point de terminaison. Les opérations remplacent la valeur racine.

  ```yaml title="openapi.yaml"
  openapi: '3.0.3'
  info: ...

  # Activer le proxy pour toutes les opérations
  x-enable-proxy: true

  paths:
    /health:
      get:
        summary: Vérification de l’état
        # Désactiver pour une seule opération
        x-enable-proxy: false
        responses:
          '200':
            description: OK
  ```

  En savoir plus dans [Utilisation du proxy OpenAPI](/fr/docs/creer-du-contenu/openapi/guides/using-openapi-proxy).
</Expandable>

<Expandable title="x-codeSamples">
  Affichez, masquez ou incluez des exemples de code personnalisés pour un bloc OpenAPI.

  **Champs**

  | Nom du champ | Type | Description |
  | --- | :---: | --- |
  | `lang` | string | Langage de l’exemple de code. La valeur doit être l’une des suivantes [liste](https://github.com/github/linguist/blob/master/lib/linguist/popular.yml) |
  | `étiquette` | string | Étiquette de l’exemple de code, par exemple `Node` ou `Python2.7`, *facultatif*, `lang` est utilisé par défaut |
  | `source` | string | Code source de l’exemple |

  ```yaml title="openapi.yaml"
  openapi: '3.0'
  info: ...
  tags: [...]
  paths:
    /example:
      get:
        summary: Exemple de résumé
        description: Exemple de description
        operationId: examplePath
        responses: [...]
        parameters: [...]
        x-codeSamples:
          - lang: 'cURL'
            label: 'CLI'
            source: |
              curl -L \\
              -H 'Authorization: Bearer <token>' \\
              'https://api.gitbook.com/v1/user'
  ```
</Expandable>

<Expandable title="x-enumDescriptions">
  Ajoutez une description individuelle pour chacune des `enum` valeurs de votre schéma.

  ```yaml title="openapi.yaml"
  openapi: '3.0'
  info: ...
  components:
    schemas:
      project_status:
        type: string
        enum:
          - LIVE
          - PENDING
          - REJECTED
        x-enumDescriptions:
          LIVE: Le projet est en ligne.
          PENDING: Le projet est en attente d’approbation.
          REJECTED: Le projet a été rejeté.
  ```
</Expandable>

<Expandable title="x-internal | x-gitbook-ignore">
  Masquez un point de terminaison de la référence de votre API.

  ```yaml title="openapi.yaml"
  openapi: '3.0'
  info: ...
  tags: [...]
  paths:
    /example:
      get:
        summary: Exemple de résumé
        description: Exemple de description
        operationId: examplePath
        responses: [...]
        parameters: [...]
        x-internal: true
  ```
</Expandable>

<Expandable title="x-stability">
  Marquez les points de terminaison qui sont instables ou en cours.

  Valeurs prises en charge : `experimental`, `alpha`, `beta`.

  ```yaml title="openapi.yaml"
  openapi: '3.0'
  info: ...
  tags: [...]
  paths:
    /example:
      get:
        summary: Exemple de résumé
        description: Exemple de description
        operationId: examplePath
        x-stability: expérimental
  ```
</Expandable>

<Expandable title="deprecated">
  Indiquez si un point de terminaison est obsolète ou non. Les points de terminaison obsolètes afficheront des avertissements de dépréciation sur votre site publié.

  ```yaml title="openapi.yaml"
  openapi: '3.0'
  info: ...
  tags: [...]
  paths:
    /example:
      get:
        summary: Exemple de résumé
        description: Exemple de description
        operationId: examplePath
        responses: [...]
        parameters: [...]
        deprecated: true
  ```
</Expandable>

<Expandable title="x-deprecated-sunset">
  Ajoutez une date de fin de prise en charge à une opération obsolète.

  Valeurs prises en charge : **ISO 8601** format (AAAA-MM-JJ)

  ```yaml title="openapi.yaml"
  openapi: '3.0'
  info: ...
  tags: [...]
  paths:
    /example:
      get:
        summary: Exemple de résumé
        description: Exemple de description
        operationId: examplePath
        responses: [...]
        parameters: [...]
        deprecated: true
        x-deprecated-sunset: 2030-12-05
  ```
</Expandable>
