### 概要

Azure AD を使用した認証アクセスで GitBook サイトをセットアップする手順は次のとおりです:

### 1\. Azure AD でアプリ登録を作成する

まず Microsoft Entra ID ダッシュボードでアプリ登録を作成します。このアプリ登録により、GitBook の Azure AD 統合は、サイトへのアクセスを許可する前にユーザーのIDを検証するためのトークンを要求できるようになります。

1. Microsoft Entra ID 管理者にサインインする [ダッシュボード](https://entra.microsoft.com/).
2. に移動します **ID** \> **アプリケーション** \> **アプリ登録** 左側のサイドバーから。
3. をクリックします <strong>\+ 新規登録、</strong> そして登録に名前を付けます。
4. 次の項目の下で <strong>対応するアカウントの種類、</strong> 「<strong>この組織ディレクトリ内のアカウントのみ（既定のディレクトリのみ - シングルテナント）</strong>.
5. Redirect URI フィールドは今は空のままにしておいてください。後で入力する必要があります。
6. クリックして **登録** してアプリ登録を完了します。<br />

   <Image src="https://test-dai.imgix.net/org-4afef969-21f9-40f3-b5b8-b06c8b6cf68f/doc-22a3b060-9539-4176-97e4-49120e02f5d1/2da0684d25472e7f-spaces-NkEGS7hzeqa35sMXQZ4X-uploads-uB6p6HxRmveHp1cfsiKa-azure_ad_integration_re.png?fm=auto&auto=compress%2Cformat" alt="An Azure screenshot showing how to register an Azure AD app" caption="GitBook VA 統合用のアプリを登録します。" />
7. その後、新しいアプリ登録の **概要** 画面が表示されます。以下をコピーして控えてください。 **アプリケーション（クライアント）ID** 、 **ディレクトリ（テナント）ID**.<br />

   <Image src="https://test-dai.imgix.net/org-4afef969-21f9-40f3-b5b8-b06c8b6cf68f/doc-22a3b060-9539-4176-97e4-49120e02f5d1/89ea39a6b472459e-spaces-NkEGS7hzeqa35sMXQZ4X-uploads-ETQziXVuqGnho8GGOVBZ-azure_ad_integration_ap.png?fm=auto&auto=compress%2Cformat" alt="An Azure screenshot showing the app registration overview" caption="新しく作成したアプリ登録の概要。" />
8. をクリックします **証明書またはシークレットを追加する**。次の **証明書とシークレット** 画面が表示されます:<br />

   <Image src="https://test-dai.imgix.net/org-4afef969-21f9-40f3-b5b8-b06c8b6cf68f/doc-22a3b060-9539-4176-97e4-49120e02f5d1/894a8961101ee978-spaces-NkEGS7hzeqa35sMXQZ4X-uploads-nXJbnpnGhOI6Udjrx8bS-azure_ad_integration_cl.png?fm=auto&auto=compress%2Cformat" alt="An Azure screenshot showing where to add a certificate or secret" caption="証明書またはシークレットを追加します。" />
9. をクリックします <strong>\+ 新しいクライアント シークレット</strong>.
10. シークレットに適切な説明を入力し、次をクリックします **追加する**.
11. コピーして以下を控えてください **値** フィールド（<em>**しません** シークレット ID</em>）今作成したシークレットのもの。

### 2\. Azure AD 統合をインストールして構成する

Azure AD アプリ登録を作成したら、次の手順は GitBook に Azure AD 統合をインストールし、先ほど生成した資格情報を使用して Azure アプリケーションにリンクすることです:

1. 以下のサイトに移動します [認証アクセスを有効にしている](/ja/docs/gong-kai/site-audience/authenticated-access/enabling-authenticated-access#enable-authenticated-access) そして Azure AD を ID プロバイダーとして使用したいサイト。
2. 次をクリックします **統合** サイト設定の右上にあるボタン。<br />

動作を確認するには、「訪問」をクリックします。Azure でサインインするよう求められます。これにより、サイトが Azure を使用した認証アクセスの背後で公開されていることが確認できます。

<Callout kind="info">
  公開されたコンテンツの URL にアクセスし、Azure の認証情報でログインすると、管理者に「承認を依頼する」必要があることを示す画面が表示される場合があります。管理者は公開されたコンテンツの URL にアクセスしてログインし、組織を代表して承認を与えることでこの要求を承認できます。
</Callout>

### 3\. アダプティブコンテンツ用に Azure AD を構成する（オプション）

認証アクセスサイトでアダプティブコンテンツ機能を活用するには、認証トークンに追加のユーザー情報をクレームとして含めるよう Azure AD アプリ登録を構成します。

これらのクレームはキーとバリューのペアとして表され、GitBook に渡されて、次の用途に使用できます [コンテンツを適応させる](/ja/docs/gong-kai/adaptive-content/adapting-your-content) ために使われます。

Azure AD はさまざまな種類とレベルのクレームをサポートしており、それぞれ設定方法が異なります:

- **標準クレーム**：トークンに含められることがある一般的なクレームですが、既定では常に存在するとは限りません。

<Callout kind="info">
  Azure AD はパフォーマンスのためにトークンサイズを最適化しています。その結果、多くのクレームは **しません** 既定ではトークンに含まれておらず、アプリケーションから明示的に要求する必要があります。次のようなクレームを確実に含めるには `email` , `groups` または `roles` 含めるには、これらを明示的に **オプショナル クレーム**.
</Callout>

- **オプショナル クレーム**：アプリケーションで有効にできる追加の事前定義クレーム。
- **カスタム クレーム**：Azure AD のカスタム ユーザー属性またはカスタム クレーム プロバイダーを介した外部システムから取得されるクレーム。

Azure AD アプリによって生成されるトークンにこれらのさまざまな種類のクレームを含める方法の詳細については、次の Microsoft Entra のドキュメント ガイドを参照してください:

- [ユーザー属性](https://learn.microsoft.com/en-us/entra/external-id/customers/how-to-add-attributes-to-token)
- [オプショナル クレーム](https://learn.microsoft.com/en-us/entra/identity-platform/optional-claims?toc=%2Fentra%2Fexternal-id%2Ftoc.json&bc=%2Fentra%2Fexternal-id%2Fbreadcrumb%2Ftoc.json&tabs=appui)
- [カスタム クレーム](https://learn.microsoft.com/en-us/entra/identity-platform/custom-claims-provider-overview)

GitBook に送る適切なクレームを設定・構成したら、「[コンテンツの適応](/ja/docs/gong-kai/adaptive-content/adapting-your-content)」に移動して、サイトの設定を続けてください。
