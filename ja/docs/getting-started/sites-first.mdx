## GitBook のサイト優先ワークスペース

GitBook は現在、ドキュメントサイトを中心に整理されています。アプリ内のすべては公開するサイトを中心に配置されるため、編集時に見える内容は、読者が閲覧時に見る内容と一致します。

このページでは、ワークスペースと、それが既存のコンテンツにとって何を意味するのかを説明します。

### なぜサイトワークスペースなのか

以前の GitBook では、作業はスペースとコレクションを中心に整理され、サイトはスペースをつなぎ合わせる形でその上に構築されていました。そのため、アプリ内で操作する構造と、公開したサイトの構造は、必ずしも一致していませんでした。

サイトワークスペースは、その差を解消します。組織にはサイトが含まれ、すべてのコンテンツはサイト内の **セクション**として存在します。編集する階層が、そのまま読者が利用する階層になります。

### 新しくなった点

#### ホームにすべてのサイトが表示される

GitBook を開くと、組織の **ホーム**に移動します。ここには、ドキュメントサイト、最近の変更、組織全体のツールがひとまとめに表示されます。どこからでもここに戻るには、サイドバー上部の切り替えを使ってください。

#### サイドバーには組織ではなくサイトが表示される

サイトを開くと、サイドバーはそのサイトのコンテンツツリーに置き換わります。これは、公開サイト上で訪問者が見る構造と同じです。任意のセクションへ直接移動し、文脈を切り替えることなく編集を始められます。

サイドバー内のコンテンツツリーは読み取り専用です。サイトを再構成するには、 **構造エディター**を開いてください。これは Site settings の旧 Structure タブに代わる専用画面です。そこで行った変更は、すぐにサイドバーにも反映されます。

#### セクションがスペースに置き換わる

サイト内のコンテンツは現在 **セクション**として存在します。以前の GitBook を使ったことがあるなら、セクションは、サイトにリンクされたスペースとして知っていたものです。エディターでの動作は同じです。変わったのは、それらがどこに存在し、サイトからどのように設定を継承するかです。

<Callout kind="alert">
  GitBook API では、セクションは引き続き `space` オブジェクトとして表されます。API 統合や Git Sync に変更はありません。
</Callout>

#### サイトツールに、ワンクリックでアクセス

Insights、Analytics、Customization、Site settings は、現在ではサイトのサイドバー内の項目となり、メインビューで開きます。もう、階層化された設定をたどって探す必要はありません。各画面の動作自体はこれまでとまったく同じです。

#### 下書きセクション

新しいセクションはまず **下書き**として作成されます。サイトにリンクされ、チームが編集できますが、訪問者には表示されません。準備ができたら、下書きを個別に公開するか、構造エディターから複数まとめて公開できます。

下書きがサイトでどのように表示されるかを確認するには、サイトプレビューを **公開中** と **公開中 + 下書き**.

#### という表示に切り替えてください。

組織設定を、状況に応じて表示

#### 組織設定が画面全体を占有することはなくなりました。組織レベルで、組織のホームと並んで文脈に応じて開くため、現在の場所を見失うことなく組織全体のオプションを調整できます。

サイト継承の権限

セクションは、コレクションではなくサイトから権限を継承できます。メンバーが複数の経路からアクセス権を持っている場合は、最も権限の広い付与が適用されます。Enterprise プランでは、サイト間で共有されるセクションは、最も広いアクセス権を継承します。

### これはスペースごとのオプトインです。オプトインしないコンテンツには、既存のコレクションベースの権限が保持されます。

削除も非公開化もされません。

- すでにサイトにリンクされているスペースは、そのサイトのセクションになります。
- どのサイトにもリンクされていないスペースは、新しい **すべてのコンテンツ** セクションに、サイトと並んで、見慣れたツリービューで表示されます。コレクションはフォルダとしてそこに保持されます。
- 組織内のすべてのスペースがいずれかのサイトに属している場合、すべてのコンテンツセクションは表示されません。
