あなたの [role](/ja/docs/gong-tong-zuo-ye/member-management/roles) サイト上での役割によって、そのサイトで作業するときに何ができるかが決まります。コンテンツの閲覧から、構造、設定、公開の変更まで含まれます。このページでは、サイトの管理において各役割で何が可能になるかを説明します。メンバーがサイトで特定の役割を持つようになる仕組みについては、参照してください [権限と継承](/ja/docs/gong-tong-zuo-ye/member-management/permissions-and-inheritance).

### サイト上で各役割でできるようになること

<Callout kind="info">
  各役割には、それより下の役割でできることはすべて含まれます。
</Callout>

| Role | できること |
| --- | --- |
| **管理** | すべて: サイト設定、公開、メンバー、請求、連携 |
| **作成者** | サイトの構造を再編成する: セクションとバリアントの追加、公開、名前変更、並べ替え、削除 |
| **レビュー担当者** | 変更リクエストをマージする — その内容を公開中のサイトに反映する |
| **エディター** | 変更リクエスト内のページコンテンツを編集し、レビューに提出し、追加する **draft** セクションとバリアント |
| **コメント投稿者** | コンテンツを読んでコメントを残す |
| **閲覧者** | 閲覧専用アクセス |

#### 管理者 — 完全な制御

サイト全体に影響する操作には、個別のコンテンツではなく管理者権限が必要です:

- サイト設定 — タイトル、公開設定、カスタムドメイン、既定のセクションまたはバリアント。
- サイトの公開と公開解除。
- 個別のバリアントの上書きではなく、サイト全体のブランディングとカスタマイズ。
- 役割の上書きを含む、サイト上のメンバーとチームの管理。
- MCP サーバーを含む連携のインストールと設定。
- リダイレクト、共有リンク、およびサイトのプライベートサイト認証の管理。
- AIアシスタント、その知識ソース、フィードバックチャネルの設定。
- サイトの請求とプラン。

ある操作が1ページや1セクションだけでなく、すべての閲覧者やすべての編集者に影響する内容を変更する場合は、管理者権限が必要です。

<Callout kind="alert">
  組織の管理者は、サイトごとの役割設定に関係なく、組織内のすべてのサイトで常にサイト管理者権限を持ちます。特定のサイトで組織管理者により低い役割を与えることはできません。
</Callout>

#### 作成者 — サイトの構成を整える

作成者は、サイトの構造 — 目次を構成するセクション、セクショングループ、バリアント — を管理できるようになります:

- セクション、バリアント、またはグループを直接 **公開済み** 下書きだけでなく、コンテンツとして追加する。
- 編集者が作成した下書きを公開したり、公開済みコンテンツを下書きに戻したりする。
- セクション、グループ、バリアントの名前変更、並べ替え、移動を行う。
- セクションまたはバリアントを削除する。
- タイトルなど、個々のバリアントのブランディング上書きをカスタマイズする。

要するに、作成者はサイト全体の管理権限がなくても、サイトの構成を完全に作り直せます。

#### レビュー担当者 — コンテンツ変更のマージ

レビュー担当者は、編集者に次の機能を1つ追加します: **変更リクエストのマージ**、これによりその内容がそのまま公開中のサイトに反映されます。これによりレビュー担当者は、サイトの構造や設定には触れられないものの、公開済みコンテンツを実際に変更できる最初の役割になります。

<Callout kind="info">
  マージ権限はサイト単位ではなくスペース単位で定義されます。サイトを構成するどのスペースに適用される場合も同じレビュー担当者の役割です。マージするにはレビュー担当者権限があれば十分で、変更リクエストを開いた本人である必要はありません。
</Callout>

#### 編集者 — 日々のコンテンツ作業

編集者は変更を行うための入口です。編集者は次のことができます:

- 変更リクエストを送信してページコンテンツを編集できます。これは他のスペースと同じです。変更はすぐには公開されず、レビュー担当者以上がマージするまで提案のまま残ります。
- サイトの構造に新しいセクションまたはバリアントを追加する — ただし、あくまで **draft**。下書きコンテンツは、作成者以上の権限を持つ人が公開するまで、公開中のサイトには表示されません。
- GitBook の AI コンテンツ品質スキャンで見つかった指摘を解決する。

編集者は自分自身の変更リクエストも他人の変更リクエストもマージできません — それにはレビュー担当者以上の権限が必要です。

<Callout kind="info">
  編集者に下書きの構造を追加させつつ、それを公開させないことで、書き手は読者に見える内容を誤って変更することなく、新しいセクションやバリアントをレビュー用に準備できます。
</Callout>

#### コメント投稿者 — 閲覧とコメント

コメント投稿者には閲覧者アクセスが含まれ、コメントを残す機能が追加されます。どちらの役割もサイトのコンテンツや設定を変更できません。

#### 閲覧者 — 閲覧

閲覧者アクセスでは、ダッシュボードでサイトを開き、その構造を閲覧し、公開済みコンテンツを読むことができます。

### これを管理する場所

サイトのメンバー、その役割、既定の権限レベルは、サイト設定 → メンバーから管理します **サイト設定 → メンバー**、サイトへの管理者アクセス権を持つ人なら誰でも行えます。を参照してください [権限と継承](/ja/docs/gong-tong-zuo-ye/member-management/permissions-and-inheritance) その既定設定、チームアクセス、メンバー個別の上書きがどのように組み合わさってメンバーの役割が決まるかについて。
