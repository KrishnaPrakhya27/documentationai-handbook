## ユーザーが実際に読むドキュメント

ユーザーは人間であり、そのAIエージェントでもあります — GitBookはその両方に向けて公開します。エディタで書く、エージェントから操作する、またはGitから同期することができます。

[クイックスタート](/ja/docs/getting-started/quickstart) [GitBook MCP](/ja/docs/docs-as-code/gitbook-mcp)

### どのように作業したいですか？

同じドキュメント、3つの取り込み方法。ほとんどのチームは複数を使います。

<Columns cols={3}>
  <Card title="エディタで" icon="pointer">
    視覚的に書いて公開。ターミナルに触れずに、ブロック、変更リクエスト、レビューまで行えます。

    [クイックスタート](/ja/docs/getting-started/quickstart)

    [コンテンツを整形](/ja/docs/kontentsuwo/formatting)

    [ドキュメントサイトを公開する](/ja/docs/gong-kai/publish-a-docs-site)
  </Card>

  <Card title="エージェントから">
    Claude、Cursor、その他のMCPクライアントからGitBookを操作。下書き作成、再構成、変更リクエストの作成ができます。

    [GitHub & GitLab Sync](/ja/docs/docs-as-code/git-sync)

    [GitBook MCP](/ja/docs/docs-as-code/gitbook-mcp)

    [Agent skills](/ja/docs/docs-as-code/ai-coding-assistants-and-skillmd)
  </Card>

  <Card title="コードで" icon="code">
    Gitから同期し、CLIでスクリプト化するか、API上で構築して独自コンポーネントを公開できます。

    [GitBook CLI](/ja/docs/docs-as-code/gitbook-cli)

    [API reference](/en/docs/developers/gitbook-api/api-reference)

    [Build a custom component](/en/docs/developers/integrations/quickstart)
  </Card>
</Columns>

### 標準搭載のAI

2つはあなたが書いている間にあなたのために働き、3つは公開後に読者のために働きます。

<Columns cols={3}>
  <Card title="GitBook Agent" href="/ja/docs/gitbook-agent/overview">
    一緒に書く

    下書き、編集、変更リクエストのレビュー、そしてスタイルガイドに照らして不足点を指摘します。
  </Card>

  <Card title="AIアシスタント" href="/ja/docs/notamenoai/gitbook-ai-assistant">
    読者に回答する

    サイドバーまたは検索ボックスで、ドキュメントや接続されたサポートソースをもとにサイト上の質問に回答します。
  </Card>

  <Card title="AI インサイト" href="/ja/docs/anaritikusu/ai-insights">
    ドキュメントを改善する

    訪問者が何を尋ねているかを確認し、ドキュメントの知識ギャップを特定します。
  </Card>

  <Card title="ドキュメントのためのMCP" href="/ja/docs/notamenoai/mcp-servers-for-published-docs">
    エージェントに提供する

    公開済みドキュメントをツールとして提供し、顧客のエージェントが正しく読めるようにします。
  </Card>
</Columns>
