GitBook’s editor makes it easy to create and customize documentation, whether you’re starting fresh or working in an existing space.

This video and guide will take you through GitBook’s native editor, covering:

- Creating [change requests](/en/docs/collaborate/change-requests) to edit content
- Editing [page titles, descriptions, and icons](/en/docs/create-content/content-structure/page#pages)
- Configuring [page options and layouts](/en/docs/create-content/content-structure/page#page-options)
- Changing a page’s [visibility and indexing settings](/en/docs/create-content/content-structure/page#visibility)
- Adding and editing [blocks](/en/docs/create-content/blocks#inserting-a-new-content-block), [Markdown](/en/docs/create-content/formatting/markdown), and content
- Syncing edits with [Git Sync](/en/docs/docs-as-code/git-sync)
- and more!

<Steps>
  <Step title="Start a new change request" titleType="h3">
    To edit published content, start by creating a **new change request**. This gives you a dedicated place to make and review edits, without pushing them live right away.

    If you’re new to the workflow, start with [change requests](/en/docs/collaborate/change-requests).
  </Step>

  <Step title="Set up your page" titleType="h3">
    You can set the **page title** at the top. This is what readers see in the sidebar.

    You can also add a **page description** and an [icon/emoji](/en/docs/create-content/content-structure/page#add-an-icon-or-emoji-to-your-page).
  </Step>

  <Step title="Configure page options" titleType="h3">
    Open [**Page options**](/en/docs/create-content/content-structure/page#page-options) to control layout and presentation.

    Use it to pick a **layout** (including templates like landing pages). You can also switch block width between **default** and **full width**.

    If you need a cleaner view, hide the page title, description, sidebars, or footer. These overrides apply only to the current page.
  </Step>

  <Step title="Control page visibility" titleType="h3">
    GitBook gives you fine-grained control over who can see content. You can hide a page from **navigation** but still share it via a direct link.

    You can also control discoverability:

    - Include or exclude the page from [**search indexing**](/en/docs/create-content/content-structure/page#visibility).
    - Allow or block [**web crawling**](/en/docs/create-content/content-structure/page#visibility) (for tools like Google or ChatGPT).
  </Step>

  <Step title="Edit content with blocks" titleType="h3">
    You can start typing to add content at any time.

    Type `/` to open the [**block insert menu**](/en/docs/create-content/blocks#inserting-a-new-content-block), then search for what you need. Common blocks include tables, cards, expandables, tabs, and more.

    If you prefer keyboard-first formatting, GitBook supports [Markdown](/en/docs/create-content/formatting/markdown) too.
  </Step>

  <Step title="Add integrations and advanced content" titleType="h3">
    The insert menu also lets you pull in more powerful content:

    - **Integrations** installed in your space (GitHub files, forms, embeds)
    - **Reusable content** for shared snippets
    - **OpenAPI specifications** for interactive API docs
  </Step>
</Steps>
