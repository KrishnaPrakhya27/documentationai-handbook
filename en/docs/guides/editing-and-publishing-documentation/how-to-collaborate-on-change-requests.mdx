Change requests are GitBook’s way of safely collaborating on documentation — similar to pull requests for code. They let you propose, review, and refine updates before anything goes live.

This video and guide will take you through change requests in GitBook, covering:

- Creating [change requests](/en/docs/collaborate/change-requests) to edit content
- Reviewing edits with [diff view](/en/docs/collaborate/change-requests/change-requests-in-a-space#diff-mode)
- Tracking changes in the **Changes** tab
- [Previewing changes](/en/docs/collaborate/change-requests/change-requests-in-a-space#previewing-a-change-request)
- Merging and publishing your content live

<Steps>
  <Step title="Create a change request" titleType="h3">
    Create a **change request** before editing published docs. This keeps your work separate from live content.

    If you’re new to the workflow, start with [change requests](/en/docs/collaborate/change-requests).
  </Step>

  <Step title="Make and review edits" titleType="h3">
    Edit content inside the change request, like you normally would. Use [**comments**](/en/docs/collaborate/comments) to leave feedback and collaborate in-context.
  </Step>

  <Step title="Track changes and preview" titleType="h3">
    Open the **Changes** tab (aka [diff view](/en/docs/collaborate/change-requests/change-requests-in-a-space#diff-mode)) to review what’s been modified.

    Use [**Preview**](/en/docs/collaborate/change-requests/change-requests-in-a-space#previewing-a-change-request) to see exactly what will ship after merge.
  </Step>

  <Step title="Request reviews (optional)" titleType="h3">
    [Request a review](/en/docs/collaborate/change-requests/change-requests-in-a-space#request-a-review-on-a-change-request) when you need another set of eyes. This keeps the workflow clear and encourages discussion before publishing.

    If you don’t tag reviewers, everyone with reviewer permissions in the space gets a notification. If the space has no reviewers, GitBook notifies the next role above reviewer instead.

    If you need tighter controls, combine reviews with [merge rules](/en/docs/collaborate/merge-rules).
  </Step>

  <Step title="Merge when ready" titleType="h3">
    When everything looks good, click **Merge**. Your changes will go live immediately.
  </Step>

  <Step title="Use merge rules (optional)" titleType="h3">
    Set up **merge rules** to define what must happen before merge. For example, require one or more reviews for approval-heavy teams.
  </Step>
</Steps>
