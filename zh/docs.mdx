## 用户真正会阅读的文档

你的用户既是人类，也是他们的 AI 代理——GitBook 会同时面向两者进行发布。可在编辑器中编写，让你的代理来驱动，或从 Git 同步。

[快速入门](/zh/docs/getting-started/quickstart) [GitBook MCP](/zh/docs/wen-dang-ji-dai-ma/gitbook-mcp)

### 你想如何工作？

同一套文档，三种进入方式。大多数团队会使用不止一种。

<Columns cols={3}>
  <Card title="在编辑器中" icon="pointer">
    以可视化方式编写和发布。无需接触终端即可使用区块、变更请求和审阅。

    [快速入门](/zh/docs/getting-started/quickstart)

    [格式化内容](/zh/docs/chuang-jian-nei-rong/formatting)

    [发布一个文档站点](/zh/docs/fa-bu/publish-a-docs-site)

  <Card title="通过你的代理">

    [GitHub 和 GitLab 同步](/zh/docs/wen-dang-ji-dai-ma/git-sync)

    [GitBook MCP](/zh/docs/wen-dang-ji-dai-ma/gitbook-mcp)

### 开箱即用的 AI

其中两个会在你写作时为你工作。另三个会在发布后为你的读者服务。

<Columns cols={3}>
  <Card title="GitBook Agent" href="/zh/docs/gitbook-agent/overview">
    与你一起写作

    起草、编辑、审阅变更请求，并根据你的风格指南标记缺口。
  </Card>

  <Card title="AI 助手" href="/zh/docs/wei-du-zhe-ti-gong-de-ai/gitbook-ai-assistant">
    回答读者问题

    在侧边栏或搜索框中，基于你的文档和连接的支持来源回答你网站上的问题。
  </Card>

  <Card title="AI 洞察" href="/zh/docs/fen-xi/ai-insights">
    改进文档

    查看访问者在问什么，并识别文档中的知识缺口。
  </Card>

  <Card title="适用于你文档的 MCP" href="/zh/docs/wei-du-zhe-ti-gong-de-ai/mcp-servers-for-published-docs">
    服务代理

    将你已发布的文档作为工具，让你客户的代理能够正确读取它们。
  </Card>
