## GitBook 中以站点为先的工作区

GitBook 现在围绕你的文档站点进行组织。应用中的一切都围绕你发布的站点来安排，因此你在编辑时看到的内容，与访问者在阅读时看到的内容一致。

此页面解释了该工作区，以及它对你现有内容意味着什么。

### 为什么采用站点工作区

以前，GitBook 会围绕空间和集合来组织你的工作，而站点则是通过将这些空间连接起来构建在其之上的。这意味着你在应用中浏览的结构，从来都不太能与已发布站点的结构完全一致。

站点工作区弥合了这一差距。你的组织包含站点，每一部分内容都作为一个 **部分**存在于站点中。你编辑的层级，就是读者看到的层级。

### 新增内容

#### 主页显示你所有的站点

当你打开 GitBook 时，你会进入你的组织 **主页**：你的文档站点、最近的更改以及组织级工具，都在一个地方。若要从任何位置返回到这里，请使用侧边栏顶部的切换器。

#### 侧边栏显示的是你的站点，而不是你的组织

打开某个站点后，侧边栏会切换为该站点的内容树，也就是访问者在你已发布站点上看到的相同结构。你可以直接导航到任意部分并开始编辑，无需切换上下文。

侧边栏中的内容树是只读的。要重新组织你的站点，请打开 **结构编辑器**，这是一个专用界面，替代了站点设置中的旧“结构”选项卡。你在那里所做的更改会立即反映到侧边栏中。

#### 部分取代空间

站点中的内容现在位于 **部分**中。如果你以前使用过 GitBook，那么这里的“部分”就是你所熟悉的、链接到某个站点的空间。部分在编辑器中的工作方式相同。变化在于它们的存放位置，以及它们如何从所属站点继承设置。

<Callout kind="alert">
  在 GitBook API 中，部分仍然表示为 `空间` 对象。对于 API 集成或 Git Sync 来说，没有任何变化。
</Callout>

#### 站点工具，一键可达

洞察、分析、自定义和站点设置现在都是站点侧边栏中的项目，并会在主视图中打开。你不再需要在层层嵌套的设置中寻找它们。这些界面本身的工作方式与以前完全相同。

#### 草稿部分

新部分开始时是 **草稿**：已链接到你的站点，可由你的团队编辑，但访客不可见。准备好后，你可以单独发布某个草稿，或在结构编辑器中一次发布多个草稿。

要查看草稿在你站点上的显示效果，请在站点预览中切换 **实时** 和 **实时 + 草稿**.

#### 上下文中的组织设置

组织设置不再占据整个屏幕。它们会在组织级别以内联方式打开，与你的组织主页并列显示，因此你可以调整组织范围内的选项，而不会丢失当前位置。

#### 站点继承权限

部分可以继承来自其站点的权限，而不是来自集合。当某个成员通过多个路径获得访问权限时，会应用最宽松的授权。在 Enterprise 方案中，跨站点共享的部分会继承最广泛的访问权限。

这项功能按每个空间单独启用。你未启用的内容会保留现有的基于集合的权限。

### 现有空间和集合会发生什么

不会删除或取消发布任何内容。

- 已链接到站点的空间会成为该站点的部分。
- 未链接到任何站点的空间会显示在新的 **全部内容** 部分中，与你的站点一起显示在熟悉的树状视图里。集合会在那里以文件夹的形式保留。
- 如果你组织中的每个空间都属于某个站点，那么“全部内容”部分就不会出现。
